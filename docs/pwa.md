# Offline support (PWA)

The app is installable and, after one visit, works without a network. This
document records the decisions behind that, because several of them look odd
until you know what failed first.

## What is built

- `static/manifest.webmanifest` — name, theme, `standalone` display, and the icon
  set generated by `scripts/generate-icons.py` (visible in `static/icons/`).
  `start_url`/`scope` are **relative** (`./`), so the same file works at `/` and
  under a sub-path such as `/KrimiMap/`.
- `scripts/build-sw.mjs` — runs after `vite build` and generates `build/sw.js`
  plus the Workbox runtime with `generateSW`. Precache: every emitted
  `html/js/css/svg/png/ico/woff2/webmanifest/json` up to 2 MiB
  (48 entries, ~401 KiB in the latest verified build; the optional WebLLM chunk
  is reported and excluded).
- `src/lib/pwa/register.ts` — registration, update detection, `SKIP_WAITING`
  hand-shake.
- `src/lib/pwa/status.ts` — framework-free state machine for what the UI shows.
- `src/lib/components/ConnectionPill.svelte` / `PwaNotice.svelte` — the header
  pill and the "offline ready"/"update available"/error notices.

## Why not `vite-plugin-pwa`

Both variants failed for concrete reasons, not taste:

1. Its `closeBundle` runs **before** `adapter-static` writes `build/`, so the
   worker it generated was deleted again by the adapter. `outDir: 'build'`
   changed which directory the plugin globbed, not the ordering.
2. SvelteKit never calls `transformIndexHtml`, so the plugin cannot inject the
   manifest link or the registration script — it warns about exactly that, and
   is only safe with `injectRegister: false`.
3. Assets above 2 MiB are a build **error** by default, which is right for an app
   bundle but wrong for the WebLLM spike.

Running Workbox as an explicit post-build step solves all three: the precache
manifest is computed from the finished `build/`, and the registration is 60
lines of code we can read.

## Routing and the service worker

The worker deliberately has **no** `navigateFallback`. A single fallback document
means every deep link gets the root shell, whose relative asset URLs then resolve
below the route (`/editor/_app/…`) — the route never boots. Workbox's
`directoryIndex: 'index.html'` maps a navigation to the precached
`<route>/index.html` instead, which is exactly what a prerendered static app
needs. App routes use `?id=…` to select a local case, so `ignoreURLParametersMatching: [/^id$/]` removes only that parameter while matching the same prerendered route shell. Other query parameters remain significant; the Svelte router still receives the original URL and ID.

## Update flow

`skipWaiting: false` and `clientsClaim: true`:

- `clientsClaim` means the first visit is controlled immediately, so "offline
  ready" is not a lie.
- `skipWaiting: false` means a new deployment **waits**. The user gets a
  "Neu laden" notice; only then does the page post `SKIP_WAITING`, the worker
  takes over, `controllerchange` fires, and the page reloads. Nobody loses an
  unsaved map because a deploy happened.
- A long-lived tab checks for updates when it becomes visible again.

## What is intentionally not cached

The WebLLM spike at `/spike/webllm` bundles ~6 MB of model runtime. Precaching it
would triple the install size for a page that exists to measure inference, so it
stays online-only (`maximumFileSizeToCacheInBytes` skips it, and the build prints
a warning naming the file). Its HTML is precached, so offline the route loads and
then fails to import the runtime — acceptable for a developer harness, not for a
shipped feature. When AI generation becomes a real feature (Phase 5), it needs
its own opt-in download flow with progress and cache management, not a precache
entry.

## How it is verified

`tests/e2e/offline.spec.ts` (desktop project):

1. Load the app, wait for the worker, then `context.setOffline(true)`.
2. Reload — the shell comes from the cache, the header pill reads `Offline` with
   `data-offline-ready="true"`.
3. Click through to `/editor`, load Leaflet and the local map image from cache; then navigate directly to `/editor/` (cold navigation, like an installed app).
4. Assert no console errors, no failed requests, and that no request leaves the
   app origin.
5. Parse the manifest and fetch every declared icon.
6. Create a local case, install a waiting service-worker update, accept it, and
   confirm the saved case is still available from IndexedDB.

`tests/unit/pwa-status.test.ts` covers the UI state machine: a pending update must
survive an "offline ready" event, dismissal resets to idle, and "offline ready" is
only promised when a worker actually controls the page.

## Known limits

- A service worker cannot be served with `Cache-Control` headers on GitHub Pages;
  Workbox handles revisions itself, so this does not matter in practice.
- Pages sets no `Cross-Origin-Opener-Policy`/`Embedder-Policy`, so
  `crossOriginIsolated` stays `false` and multi-threaded WASM is unavailable.
  This is the one reason a small reverse proxy could be worth it later.
- No background sync is used: case documents are local-only in IndexedDB and have no server queue to drain.
